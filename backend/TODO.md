## 1. 创建数据库专用账号

用 root（或具备授权权限的账号）连接 MySQL 并执行：

```sql
CREATE USER 'fortune'@'localhost' IDENTIFIED BY 'fortunefinger@2026_lottery';
GRANT ALL PRIVILEGES ON fortunefinger.* TO 'fortune'@'localhost';
FLUSH PRIVILEGES;
```

**说明**

- 该账号只对 `fortunefinger` 库有权限，不使用 root 跑业务，符合最小权限原则。
- 已在 MySQL 8.0.42 实测：`GRANT ALL PRIVILEGES ON 库名.*` **包含建库权限**，即使
  `fortunefinger` 库尚不存在，授权后该账号也能自行创建它——满足
  [docs/FIRST_START.md](../../docs/FIRST_START.md) 的初始化流程需要。
- `FLUSH PRIVILEGES` 在 MySQL 8 使用 `CREATE USER` / `GRANT` 语句时**并非必需**
  （只有直接 `INSERT`/`UPDATE` 权限表才需要）。写上无害，保留亦可。
- **`'fortune'@'localhost'` 只允许本机连接。** 若 MySQL 不在本机，需改为
  `'fortune'@'%'` 或具体 IP——但这会放宽访问来源，改前请确认网络边界。

执行完把 `etc/fortune.yaml` 的 `User` / `Password` 与之对齐后，再跑迁移。

## 3. 完善超级管理员保护与延迟删除

实施顺序：

1. 增加超级管理员禁用保护，确保系统始终保留至少一个启用且未删除的超级管理员。
2. 在定时任务功能完成前，禁用状态的超级管理员可以立即删除，启用状态的超级管理员暂时拒绝删除。
3. 同步前端超级管理员操作限制。
4. 从通用定时任务表开始，实现任务创建、取消、抢占、重试、执行记录和幂等，再接入启用状态超级管理员的延迟删除。

- 普通角色即使拥有用户管理和角色管理权限，也不得编辑、禁用、删除超级管理员用户，或修改、禁用、删除 `super_admin` 角色；只有超级管理员之间可以执行这些操作。
- 系统最多允许两个用户绑定 `super_admin` 角色；只有超级管理员可以新增超级管理员绑定。
- 禁用超级管理员立即生效，但操作后必须至少保留一个启用且未删除的超级管理员。
- 删除启用状态的超级管理员时不立即删除，而是创建一条 24 小时后执行的删除任务；等待期间允许目标超级管理员正常登录。
- 目标超级管理员在删除任务创建后成功登录，应取消对应的待执行任务。登录业务后续负责写入操作日志；定时任务执行前可通过最近一笔登录日志判断其登录时间是否处于任务创建后的 24 小时内。
- 删除禁用状态的超级管理员时不创建延迟任务，可以立即执行删除，但删除后仍须至少保留一个启用且未删除的超级管理员。
- 已进入待删除状态的超级管理员不允许直接禁用；必须先取消删除任务，再执行禁用操作。
- 定时任务执行前必须重新校验目标用户、角色绑定、用户状态、登录记录、任务状态以及剩余启用超级管理员数量；任一条件不满足时取消或忽略本次执行。
- 同一个用户只能存在一条有效的超级管理员删除任务。任务执行必须幂等，并在多实例运行时避免重复消费。
- 查询和业务校验放在事务外；事务内只执行用户软删除、删除 Casbin `g` 策略和更新任务状态等数据变更操作。
- 删除事务提交成功后记录 `Info` 日志，包含 `operator_id`、目标 `user_id` 和 `username`；创建延迟删除任务成功时记录任务 ID 和计划执行时间。
- 定时任务框架及任务表需要先完成表结构设计，本阶段不实现调度与执行逻辑。
